# P006: Contract Testing

## Definition
P006 validates that the API implementation matches its specification through functional testing. It is the only principle that requires a live API endpoint, sending actual HTTP requests and verifying that responses conform to the documented contract. This principle is the operational realization of the Determinism Axiom.

## DDT Axiom Mapping
**Determinism Axiom** — Documented examples imply reproducible behavior that can be verified. If the specification states that GET /pets returns a 200 with an array of Pet objects, then the live API must exhibit exactly that behavior, deterministically and repeatedly.

## Severity
Critical

## AutoFixable
No — contract violations indicate implementation bugs or specification drift, both of which require human intervention to resolve.

## Checks Performed
1. All documented endpoints are reachable (HTTP connectivity)
2. Response status codes match documented status codes
3. Response body schemas match documented schemas (JSON Schema validation)
4. Authentication mechanisms work as documented
5. Required parameters are enforced (missing required params return 4xx)
6. Request payload validation matches schema constraints
7. Error responses match documented error schemas

## Prerequisites
- A running API endpoint (specified via `--base-url` CLI flag)
- Network connectivity to the target API
- Valid authentication credentials if the API requires them

## Mode Behavior
- **Minimal:** Not executed (contract testing is opt-in via `--mode test-only` or `--mode strict`)
- **Strict:** All 7 checks executed against the live API
- **Test-only:** Only P006 and P007 are executed (skip static analysis)

It demonstrates the core DDT thesis: that a sufficiently complete specification contains enough information to automatically verify API correctness.
