# P008: Versioning Strategy

## Definition
P008 validates proper API versioning implementation and documentation. It ensures that the API declares its version, follows semantic versioning conventions, documents deprecation policies, and provides migration guidance — enabling automated lifecycle management and backward compatibility analysis.

## DDT Axiom Mapping
**Observability Axiom** — Versioning metadata must be machine-readable for lifecycle automation. An API whose version is ambiguous or whose deprecation notices are buried in prose cannot be automatically managed by GitOps pipelines or API gateways.

## Severity
Warning

## AutoFixable
Yes — missing version fields can be scaffolded, non-semver versions can be flagged with suggested corrections, and deprecation headers can be generated for endpoints marked as deprecated in the spec.

## Checks Performed
1. API version is specified in info.version
2. Version follows semantic versioning format (major.minor.patch)
3. Versioning strategy is documented (URL path, header, query param)
4. Deprecated endpoints are marked with `deprecated: true`
5. Breaking changes are documented (changelog or x-breaking-changes extension)
6. Version compatibility information is specified (minimum client version, etc.)
7. Migration guides are referenced for major version changes
