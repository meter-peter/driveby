# P004: Schema Definitions

## Definition
P004 ensures all API requests and responses have comprehensive schema definitions with proper data types, validation rules, and constraints. It enforces that schemas are precise enough to serve as executable contracts for payload validation.

## DDT Axiom Mapping
**Completeness Axiom** — Schema definitions must be thorough enough to validate request/response payloads. A schema that lacks type constraints or validation rules is ambiguous and cannot deterministically verify data correctness.

## Severity
Warning

## AutoFixable
Yes — missing type annotations, required field markers, and basic constraints (e.g., string minLength, integer minimum) can be inferred from example values and common patterns.

## Checks Performed
1. Path parameters have schemas with types defined
2. Query parameters have schemas with types defined
3. Header parameters have schemas with types defined
4. Request body schemas are fully defined (not empty objects)
5. All schema properties have explicit data types
6. Schemas include validation constraints (pattern, min/max, etc.)
7. Required fields are marked in object schemas
8. Enum values are defined where applicable
9. Numeric properties have minimum/maximum constraints
10. String properties have minLength/maxLength or pattern constraints
