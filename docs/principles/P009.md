# P009: Test Readiness

## Definition
P009 validates that an API specification provides sufficient detail for meaningful functional and load testing. Without adequate examples, typed schemas, and response definitions, automated test generators fall back to generic placeholder values that are rejected by real API validation logic, producing false failures.

## DDT Axiom Mapping
**Determinism Axiom** — P009 ensures the preconditions for deterministic test execution: given the same specification and the same API, the generated test data will be typed and meaningful rather than dependent on arbitrary fallback heuristics.

## Severity
Warning

## AutoFixable
Partially — missing examples can be scaffolded from schema types, missing response schemas can be stubbed with generic structures, but meaningful examples require domain knowledge.

## Checks Performed
1. Path parameters have examples or typed schemas — without an example or a typed schema, parameter substitution falls back to untyped strings (`"test-value"`) that fail server-side validation for integer, UUID, or enum parameters
2. Request bodies have examples or typed schema properties — the functional tester prioritizes explicit examples, then falls back to schema-based generation; if neither is available, generated payloads are rejected by any API with input validation
3. 2xx responses have schemas defined — without response schemas, functional tests degrade to status-code-only checks with no response body validation
4. 2xx responses have examples defined — advisory check (warning, not failure); response examples improve test reporting but are not required for meaningful validation
