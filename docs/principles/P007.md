# P007: Performance Requirements

## Definition
P007 validates that the API meets performance targets and SLAs through automated performance testing. It verifies response times, throughput, error rates under load, and resource utilization against documented or configured thresholds.

## DDT Axiom Mapping
**Observability Axiom** — Performance metrics must be measurable and reportable. An API whose performance characteristics are not observable cannot be managed in a production environment. DDT extends observability from functional correctness to non-functional quality attributes.

## Severity
Warning

## AutoFixable
No — performance issues stem from implementation, infrastructure, or architectural decisions that require human analysis and remediation.

## Checks Performed
1. Response time targets met (p50, p95, p99 latency within thresholds)
2. Success rate above threshold (e.g., >= 99% for 2xx responses)
3. Error rate below threshold (e.g., <= 1% for 5xx responses under normal load)
4. Latency percentiles within documented SLA bounds
5. Throughput meets minimum requests/second target
6. Concurrent request handling (no degradation under parallel load)
7. Resource utilization within acceptable bounds (connection pool, memory)

## Prerequisites
- A running API endpoint (specified via `--base-url` CLI flag)
- Network connectivity to the target API
- Sufficient client-side resources for load generation
- Configurable thresholds (via CLI flags or config file)

## Default Thresholds
| Metric | Default | Configurable |
|--------|---------|-------------|
| p50 latency | 200ms | Yes |
| p95 latency | 500ms | Yes |
| p99 latency | 1000ms | Yes |
| Success rate | 99% | Yes |
| Error rate | 1% | Yes |
| Min throughput | 100 req/s | Yes |
| Concurrent users | 10 | Yes |

## Mode Behavior
- **Minimal:** Not executed (performance testing is opt-in)
- **Strict:** All 7 checks executed with default or configured thresholds
- **Test-only:** Only P006 and P007 are executed (skip static analysis)
