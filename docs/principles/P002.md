# P002: Documentation Quality

## Definition
P002 ensures comprehensive and high-quality API documentation. It verifies that every endpoint, parameter, schema, and response is thoroughly described, enabling both human developers and automated tools to fully understand the API contract without external knowledge.

## DDT Axiom Mapping
**Completeness Axiom** — Documentation must be thorough enough to derive test cases. An API whose documentation is incomplete cannot be deterministically tested, because the expected behavior is ambiguous.

## Severity
Critical — incomplete documentation prevents meaningful functional testing (test generators need examples, descriptions, and schema docs to produce valid test data)

## AutoFixable
Yes — missing summaries, descriptions, and operationIds can be scaffolded from endpoint structure and schema definitions.

## Checks Performed
1. All operations have summaries
2. All operations have descriptions
3. All operations have unique operationIds
4. All parameters have descriptions
5. Request bodies include examples
6. Response bodies include examples
7. Schema properties have descriptions
8. Enum values have descriptions or documentation
9. API-level description is present and non-trivial
10. Contact info and license info are specified

## Mode Behavior
- **Minimal:** Checks 1-3 (summaries, descriptions, operationIds)
- **Test-ready:** Checks 1-9 enforced (skips contact/license — not needed for test generation, but examples, schema docs, and enum descriptions are required for functional/load testing)
- **Strict:** All 10 checks enforced
